# NTEUID 抽卡存档格式 v1

官方、TapTap 和小黑盒数据转换成 NTEUID 存档模型后，按游戏 UID 合并并保存。三种查询均从合并后的存档生成图片。官方接口或令牌刷新失败时读取本地存档；没有本地记录时返回原错误。

发送 `nte抽卡记录 <TapTap user_id>` 或 `nte抽卡记录 <user_pkey>`，可将 TapTap 或小黑盒保留的旧记录存入本地。登录同一游戏角色后，发送 `nte抽卡记录` 可查看合并结果。数据源返回的游戏 UID 决定存档归属，无需预先登录 NTEUID。UID 缺失、查询失败或明细格式错误时返回提示，不写入存档。

## 文件格式

每个游戏 UID 保存为 `data/NTEUID/gacha/<uid>.json`。v1 接收塔吉多官方源、TapTap 和小黑盒，只记录已出 S 的物品及对应抽数。

```json
{
  "format": "nteuid-gacha",
  "version": 1,
  "uid": "123456789012",
  "source": "tajiduo",
  "updated_at": 1793605628,
  "pools": {
    "permanent": {
      "records": [
        {"item_id": "1039", "time_ms": 1787317673012, "pity": 1},
        {"item_id": "1039", "time_ms": 1787317673012, "pity": 54}
      ]
    }
  }
}
```

| 字段 | 约定 |
|---|---|
| `format` / `version` | 固定为 `nteuid-gacha` / `1` |
| `uid` | 游戏 UID，数字字符串 |
| `source` | 最近一次合并的来源：`tajiduo`、`taptap` 或 `xiaoheihe`；存档可同时包含三种来源的记录 |
| `updated_at` | 官方查询时间、TapTap 和小黑盒数据更新时间中的最大值，单位为 Unix 秒；读取本地时保持原值 |
| `pools` | 卡池标识到明细的映射；`limited` 为限定池，`permanent` 为常驻池，`weapon` 为弧盘池 |
| `item_id` | 官方物品 ID，角色为数字字符串，弧盘为 `fork_` 加小写字母、数字或下划线 |
| `time_ms` | 抽中时间的 Unix 毫秒时间戳；官方保留原值，TapTap 和小黑盒秒时间戳乘以 1000 |
| `time_precision` | `ms` 为毫秒精度，`s` 为秒精度；省略时为 `ms`，兼容已有官方存档 |
| `pity` | 本次出 S 所用抽数，至少为 1 |

## 合并与统计

- 同一 UID、同一卡池内，毫秒记录按 `(item_id, time_ms, pity)` 匹配。相同记录的数量取两份快照中的最大值，重复查询不会重复计数。
- 秒记录按 `(item_id, time_ms // 1000, pity)` 与毫秒记录逐条匹配，重叠项保留毫秒记录。同秒多次出 S 保留数量，未匹配的秒记录继续保留。
- 小黑盒物品 ID 转为小写，并去掉图标文件名的 `_256` 后缀，与官方 ID 对齐。
- 合并结果按 `time_ms` 降序排列。接口缺少某条记录或整个卡池时保留本地记录。
- 本地记录不按时间过期。官方已过期的记录可从 TapTap 或小黑盒补入，前提是对应数据源仍保留这些记录。
- JSON 只存明细。池级 `draw_count` 为全部 `pity` 之和，`s_count` 为记录数，`average` 为 `draw_count / s_count`；空池平均值为 0。
- 总抽数只覆盖已出 S 的区间，不包含当前未出 S 的垫抽。展示的平均抽数取整数部分，运气称号由累计抽数和 S 数计算。
- 物品名称从资源表查询。`playerOver`、官方运气称号、头像、登录凭据等不写入标准存档。
- 同一 UID 的合并写入串行执行，文件采用原子替换。

## 读取与迁移

读取时优先使用标准存档。标准存档不存在时，读取 `data/NTEUID/gacha/tajiduo/<uid>.json` 并转换成标准模型；下次接口查询成功后保存到标准路径，原文件保留。UID 不匹配或文件格式错误时停止处理，不覆盖文件。

文件格式和字段语义由本协议确定。官方、TapTap 和小黑盒查询共用存档和写入锁。本模块提供在线查询及合并入口。
